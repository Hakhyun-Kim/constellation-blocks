# ADR-001: 선택적 런타임 에셋 경계

**상태:** 채택
**날짜:** 2026-08-13
**결정자:** Constellation Defense 프로젝트

## 배경

출시급 아트 파일럿에는 GLB·오디오 같은 외부 에셋이 필요하지만, 현재 procedural
빌드는 약 1.1MiB이며 다운로드 실패 없이 즉시 시작한다. 외부 파일 때문에 엔진
규칙, 기본 시작 시간, 저사양 폴백이 결합되면 파일럿을 되돌리기 어려워진다.

필수 조건은 다음과 같다.

- 기본 URL은 외부 manifest도 요청하지 않는다.
- 파일럿 파일은 `?art=v2`에서만 지연 요청한다.
- 라이선스·해시·품질 프로필은 빌드 검사와 런타임이 같은 스키마로 해석한다.
- 파일 하나가 누락되거나 장면이 폐기돼도 procedural 전투는 계속된다.
- 장면 교체 뒤 늦게 끝난 요청은 새 장면을 건드리지 않는다.

## 결정

`src/assets/catalog.js`를 순수 manifest 계약으로 두고,
`src/gfx/asset-loader.js`를 네트워크·디코딩 경계로 둔다. `src/main.js`는
`?art=v2`일 때만 로더를 활성화해 렌더러에 주입한다. 로더는 id별 요청을 한 번만
수행하고 품질 프로필에 맞지 않는 파일은 요청하지 않으며, 모든 실패를 `null`로
돌려 호출부가 procedural 모델을 유지하게 한다. `retry()`는 manifest를 명시적으로
다시 요청하고, `dispose()`는 진행 중 요청을 취소하고 세대가 지난 결과를 버린다.

manifest는 파일마다 다음을 요구한다.

- 고유 `id`, `type`, `path`, 적용할 `profiles`
- 제작자, 원본 URL, 라이선스 이름·URL, 취득일
- 저장소 파일의 SHA-256과 첫 장면 `preload` 여부

모델·오디오 디코더는 다음 파일럿 커밋에서 타입별로 주입한다. 로더 자체는
Three.js와 Web Audio를 몰라 규칙과 번들 전략을 독립적으로 바꿀 수 있다.

## 검토한 선택지

### A. 모든 외부 로더와 에셋을 기본 번들에 포함

| 항목 | 평가 |
| --- | --- |
| 복잡도 | 낮음 |
| 첫 플레이 성능 | 나쁨 |
| 실패 격리 | 낮음 |
| 되돌리기 | 어려움 |

구현은 단순하지만 파일럿 단계부터 모든 사용자에게 다운로드·파싱 비용을 준다.

### B. opt-in manifest와 주입형 디코더

| 항목 | 평가 |
| --- | --- |
| 복잡도 | 중간 |
| 첫 플레이 성능 | 좋음 |
| 실패 격리 | 높음 |
| 되돌리기 | 쉬움 |

기본 빌드를 보존하며 같은 URL에서 전후 비교가 가능하다. 이 안을 채택한다.

### C. 전체 빌드를 ESM 코드 분할로 즉시 전환

| 항목 | 평가 |
| --- | --- |
| 복잡도 | 높음 |
| 첫 플레이 성능 | 잠재적으로 가장 좋음 |
| 배포 변경 위험 | 높음 |
| 장기 확장성 | 높음 |

최종 방향이 될 수 있지만, 현재 검증된 단일 IIFE Pages 배포를 아트 파일럿과
동시에 바꾸면 문제 원인을 분리하기 어렵다. 실제 에셋 수가 늘 때 다시 검토한다.

## 결과

- 기본 플레이와 아트 파일럿을 같은 커밋에서 안전하게 비교할 수 있다.
- 에셋 선택과 라이선스 검증을 Node에서 결정적으로 검사할 수 있다.
- 외부 파일 사용처는 비동기 폴백을 명시적으로 처리해야 한다.
- 타입별 디코더와 모델 인스턴스 수명 관리는 P0-2에서 추가해야 한다.
