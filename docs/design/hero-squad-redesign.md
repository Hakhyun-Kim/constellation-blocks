# 디자인 결정: 고정 영웅단 리디자인

- 상태: 대체됨 — `journey-campaign-redesign.md` 참조
- 적용 대상: `Constellation Defense` 공개 게임
- 결정일: 2026-08-11

## 문제

현재 게임은 실시간 3매치 전술, 소환, 동일 영웅 승급, 레시피 조합, 성 업그레이드, 별지기 성장과 메타 성장까지 한 화면에 둔다. 각각은 작동하지만, 첫 플레이에서 무엇이 핵심 선택인지 흐리고 전투의 읽기 쉬움을 낮춘다.

## 결정

랜덤 소환·벤치·판매·등급 조합·특수/신화 레시피·조합 공명을 제거한다. 플레이어는 처음부터 클래스가 정해진 이름 있는 영웅단을 운용하며, 각 영웅은 런과 별의 시련 회차에 걸쳐 레벨·경험치·전문화 선택을 유지한다.

루나는 직접 조작하는 별지기로 남는다. 나머지 영웅은 전장 배치와 성장 선택을 맡는다. 실시간 3매치는 유지하며, 매치한 길의 Flare/Tide/Bloom 전술로 영웅단이 버틸 시간을 만들고 타격을 보완한다.

## 목표 루프

1. 준비 단계에서 고정 영웅단의 배치와 이번 웨이브의 성장 선택을 정한다.
2. 전투 중 3매치로 한 길에 Flare(공격), Tide(감속), Bloom(회복·후퇴)을 적용한다.
3. 처치·웨이브 완료로 영웅 경험치를 얻고, 레벨업 때 하나의 전문화를 선택한다.
4. 보스와 30웨이브 승리 뒤 별의 시련에서 영웅·루나의 성장은 유지하고 적과 성은 다시 시작한다.

## 영웅단 규칙

- 시작 영웅은 검객, 수호자, 궁수, 마도사 네 명이다. 클래스는 고정이고 랜덤 뽑기가 없다.
- 영웅은 한 명당 하나의 전장 슬롯만 차지한다. 벤치나 복제 캐릭터는 없다.
- 영웅은 기본 공격으로 경험치를 얻고 웨이브를 완료할 때 추가 경험치를 얻는다.
- 각 영웅은 레벨업마다 전문화 포인트를 하나 얻는다. 포인트는 공격, 제어, 생존 중 해당 클래스의 세 갈래 중 하나에만 쓴다.
- 모든 수치는 `src/balance/`에 두고, 성장 선택은 순수 엔진 함수로 판정한다.

## 전술과의 연결

3매치 전술의 역할을 새 성장 시스템으로 옮기지 않는다.

- Flare는 압박받는 길을 즉시 정리해 궁수·마도사의 화력 시간이 늘어난다.
- Tide는 적을 늦춰 원거리 영웅의 누적 공격과 수호자의 저지 효과가 의미 있어진다.
- Bloom은 성과 전방 영웅이 무너질 때 회복·후퇴 기회를 만든다.

따라서 퍼즐은 영웅 성장을 대체하지 않고, 성장한 영웅을 잘 쓰게 하는 실시간 전술 선택으로 남는다.

## 제거하는 요소

- 소환 비용, 랜덤 등급, 벤치, 판매
- 동일 영웅 2명 승급
- 특수·신화 조합 캐릭터와 레시피
- 조합 별값으로 길을 여는 공명
- 조합 수와 희귀도 수집을 중심으로 한 도감/성과

## 유지하거나 바꾸는 요소

- 성 업그레이드는 유지하되, 골드는 성 보강과 영웅 성장 선택에만 사용한다.
- 루나의 레벨과 스킬 트리는 유지한다.
- 영웅 성장도 시련 회차를 통과해 유지한다. 영웅 위치·체력·전투 중 상태는 준비 단계에서 초기화한다.
- 영웅 레벨 이정표는 공격 방식 변화와 국소 이펙트로 읽히게 한다. 전체 화면 플래시는 사용하지 않는다.

## 구현 순서와 게이트

1. 결정 문서와 공개 카피를 고정한다.
2. 엔진에 고정 영웅단, 경험치, 전문화, 저장·시련 유지 규칙을 추가한다. 결정적 엔진 테스트를 먼저 둔다.
3. 소환·조합 UI를 영웅단과 성장 선택 화면으로 바꾸고, 배치·전투 표현을 이어 붙인다.
4. 사람과 같은 정보만 쓰는 밸런스 봇을 성장 선택·배치·3매치 정책으로 교체한다.
5. 엔진 검사, 전술 검사, 60회 밸런스 검사, 데스크톱·모바일 UI 스모크를 통과한 뒤 공개 카피를 갱신한다.

## 성공 기준

- 첫 웨이브 전 화면에서 소환·등급·조합을 읽을 필요가 없다.
- 플레이어는 10초 안에 영웅 배치와 3매치의 역할을 이해할 수 있다.
- 매 웨이브마다 영웅 성장, 성 보강, 길 전술 중 적어도 하나의 의미 있는 선택이 있다.
- 밸런스 봇은 소환·조합 특권 없이 성장 선택, 배치, 실제 3매치 스왑으로 기준선을 만든다.
