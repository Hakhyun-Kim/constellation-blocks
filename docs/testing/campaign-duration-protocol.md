# 캠페인·주간 도전 사람 플레이 시간 측정

Last updated: 2026-08-14

## 목적과 정직성 경계

일반 캠페인의 목표 활성 플레이 시간은 **25~40분**, 주간 도전은 **10~15분**이다.
봇의 시뮬레이션 시간이나 Codex의 브라우저 조작 시간은 사람 플레이 표본으로 기록하지
않는다. 이 문서는 측정 절차와 판정 기준만 고정하며, 2026-08-14 현재 실제 사람 표본은
아직 0건이다.

게임은 개인 식별자나 네트워크 분석 SDK 없이 기기의 `localStorage`에 최근 40개 세션만
기록한다. 툴바의 **📊 플레이 기록 내보내기** 버튼을 눌러 JSON을 내려받을 때만 기록이
기기 밖으로 복사된다. 파일에는 활성 시간, 실경과 시간, 구간별 시간, 주요 행동 횟수,
진행 체크포인트, 결과와 재도전 연결 번호가 들어간다.

## 동일 조건

1. 최신 공개 빌드에서 새 저장으로 시작한다. 캠페인은 보통 난이도, 주간 도전은 해당
   주의 `?weekly=YYYY-Www` 주소를 사용한다.
2. 기본 `art-v2`, 1배속, 관전 봇 미사용으로 플레이한다. 음소거와 절제 효과는 자유다.
3. 캠페인은 두 번째 장의 엔딩 선택까지, 주간 도전은 첫 장 7회 방어 완료까지 진행한다.
4. 휴식이나 탭 이탈은 숨김 상태로 두어 활성 시간에서 제외한다. 시작 화면에서 머문
   시간과 관전 봇 시간도 활성 시간에서 제외된다.
5. 패배 뒤 재도전은 별도 세션으로 저장하되 `retryOf`로 앞 세션과 연결한다. 캠페인
   전체 소요는 최초 시도부터 완주까지 연결된 세션의 활성 시간을 합산해 함께 기록한다.

## 표본과 판정

- 첫 외부 검증은 서로 다른 플레이어 최소 5명으로 한다. 3매치·디펜스 장르 경험을
  초보/보통/숙련으로 자가 분류한다.
- 중앙값과 p25/p75, 완주율, 패배율, 재도전율을 캠페인과 주간 도전별로 분리한다.
- 캠페인 완주자 중앙값 25~40분, 주간 도전 완주자 중앙값 10~15분을 통과 기준으로 둔다.
- 캠페인 완주율이 60% 미만이거나 보통 경험자의 첫 장 이탈률이 25%를 넘으면 길이를
  늘리기 전에 난이도·설명·전환 마찰을 먼저 고친다.
- 중앙값이 목표보다 짧지만 재도전과 선택 다양성이 충분하면 억지 반복 웨이브 대신
  선택 노드·이야기 반응을 보강한다. 목표보다 길면 전투 수보다 중복 준비·모달 시간을
  먼저 줄인다.

## 회수 체크리스트

플레이 직후 📊 버튼으로 JSON을 내보내고 다음 네 질문을 함께 받는다.

1. 처음으로 규칙을 이해했다고 느낀 순간은 언제였는가?
2. 가장 지루하거나 끊겼던 구간은 어디였는가?
3. 다시 한다면 다른 영웅·별길·엔딩을 고르고 싶은가?
4. 다음 주 도전을 열 의향이 있는가?

원본 JSON은 공개 저장소에 커밋하지 않는다. 익명 집계만 날짜·빌드 SHA·표본 수와 함께
로드맵 문서에 기록한다.

## 집계 명령과 증거 자격

한 사람당 하나의 📊 JSON을 받은 경우 다음처럼 합친다.

```powershell
npm.cmd run playtest:report -- player-a.json player-b.json player-c.json player-d.json player-e.json
```

파일 수와 실제 사람 수가 다르면 `--participants=5`처럼 검증한 사람 수를 명시한다.
게임 내부의 단일 기기 export는 사람 수를 추정하지 않으며 항상
`unverified-local`이다. 봇, Codex 브라우저 조작, `?judge=1`, `?demo`, `?sessionqa=1`
세션은 사람 표본에 포함하지 않는다. 세부 판정 분기는
`docs/design/early-access-evidence-gate.md`를 따른다.
